% Appendix D, the cubic card, band 1 --- the cubic panel of Figure 2.2,
% re-drawn with numbered chips.
%
% Modelled line for line on card_oct_sphere.tex and recipe_tet_sphere.tex: same
% macros, same pose {60}{120}, \PanelScale 2.47 (Figure 1.1's size, one notch
% under Figure 2.2's 2.6), and the panel block itself --- halo widths, blade axis
% U = (0,1,1)/sqrt2, the \drawEdge / \drawRayDisk order --- copied verbatim from
% the cube panel of platonic_solid_povms.tex.  \PanelHeader, not
% \PanelHeaderSil, and \PanelFooter deliberately NOT used: the solid's name is
% the card's title.
%
% The three grey axis names ARE drawn here, unlike the octahedron card.  That
% omission is the octahedron's own and has a measurement behind it (its
% vertices ARE the axes, so a name at radius 1.10 lands 2.67pt from the chip on
% the same ray); the cube's nearest chip centre to an axis anchor is 53.73pt
% (measured off this projection at this scale), so the names are free here and
% the panel keeps the frame Figure 1.1's tetrahedron has.
%
% Chips: ALL EIGHT (the all-V minimum projected separation is 52.05pt against
% a 9.5pt chip).  Vertex 7 points nearly at the camera (v.view = 0.972,
% projected radius 16.6pt), so its ray is a foreshortened stub and its chip
% takes the larger 11pt offset, exactly as Figure 1.1 does for the
% tetrahedron's vertex 1 --- the same geometry, the same remedy.
%
% Chips are placed AFTER the scaled scope closes, so their offsets are true page
% points; ($(vk)!-9pt!(O)$) reads "9pt beyond the tip, along the ray from the
% sphere centre", which is projection-agnostic and must not be replaced by
% hard-coded angles.
%
% Include at natural size --- no width= --- the type set here is printed type.
